# 发布部署（deploy）

执行一次完整的发布流程：验证测试 → 构建产物 → 提交并部署到目标环境（经 MCP 服务器暴露的 git/部署工具）。这是 Skill + Subagent + MCP 协同的端到端示例。

## 前置条件

- 确认部署目标与方式（由 MCP 服务器提供，如 `mcp__git__*`）。若未配置 MCP 服务器，先检查工作区 `mcp_config.json`，并向用户说明缺失的工具。
- 明确发布范围（提交信息、是否推送、部署环境）；不确定时先向用户确认，**不要**在未确认的情况下推送或部署。

## 执行步骤

1. **检查工作区状态**：调用 `mcp__git__git_status` 查看未提交变更；用 `run_command` 确认构建工具存在。
2. **运行测试**：执行项目测试命令（`npm test` / `pytest`）。测试失败则停止流程并报告，修复建议可派生 `test-generator` 子智能体处理。
3. **构建产物**：执行构建命令（`npm run build` / `npm run dist`）。构建失败则停止并报告。
4. **提交**：使用 `mcp__git__git_commit` 提交（message 用 `mcp__git__commit-message` prompt 生成或由用户提供），如配置允许再 `git_push`。
5. **部署**：按目标环境调用部署工具（推送触发 CI，或直接调用部署 MCP 工具）。等待并读取部署结果。
6. **输出报告**：汇总 变更摘要 → 测试结果 → 构建结果 → 提交 hash → 部署状态，以及任何遗留风险。

## 规则

- **高风险操作（推送/部署）必须先征得用户确认**；提交前的检查步骤可自主完成。
- 任一步骤失败即停止，输出失败原因与已完成的步骤，不要掩盖错误。
- 部署地址、密钥等敏感信息不写入对话日志。

## 完成判定

产出明确结果之一：(a) 部署成功并附上地址/提交 hash；(b) 在某一环节失败并给出失败原因与下一步建议。
