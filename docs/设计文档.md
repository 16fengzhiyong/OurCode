## 1. 文档说明

### 1.1 目的

本文档描述 OurCode IDE 的**总体架构与关键子系统设计**，为开发者提供：
- 系统架构视图（进程模型、分层、模块边界）
- 核心子系统的内部设计与关键机制
- 关键数据流与交互时序
- 设计决策（ADR）与取舍理由
- 安全模型与边界条件

### 1.2 读者

主进程 / 渲染进程开发者、插件开发者、MCP 服务器开发者、代码审查者。

### 1.3 术语表

| 术语 | 含义 |
| --- | --- |
| 主进程 | Electron 主进程（Node 环境），负责文件系统、存储、终端、网络代理 |
| 渲染进程 | Electron 渲染进程（Chromium），React UI 与 Agent 循环 |
| preload | contextBridge 暴露的白名单桥接层 |
| Agent 循环 | 渲染进程中的「LLM 请求 → 工具调用 → 结果回填」迭代循环 |
| 工具（Tool） | 暴露给 LLM 的 function-calling 工具 |
| 动态工具 | 运行时加载的工具（MCP 工具、Skill 工具） |
| Checkpoint | 写工具执行前的文件快照，用于回滚 AI 编辑 |
| MCP | Model Context Protocol，接入外部工具/资源/提示词 |

### 2.2 分层职责

| 层 | 职责 | 关键约束 |
| --- | --- | --- |
| 渲染进程 | UI 渲染、Agent 编排、LLM 调用编排 | 沙箱化（sandbox:true），无法直接访问 Node |
| Preload | 白名单 API 桥接 | 仅暴露显式声明的函数 |
| 主进程 | 文件、存储、终端、网络、子进程 | 所有 fs 路径过白名单校验 |
| 共享层 | IPC 通道常量、类型契约 | 主/渲染共用，保持单一事实源 |

### 2.3 进程安全边界

- 渲染进程启用 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`（main.ts:216-224），与 VS Code 同款策略：即使渲染进程被攻破（如 Markdown 渲染面），也无法直接触达 Node 原语。
- 渲染进程的全部能力来自 preload 暴露的 `window.electronAPI` 白名单函数。
- 出站网络请求（LLM / web）全部经主进程 `net.fetch` 代理，规避 CORS。

## 4. 主进程设计

### 4.1 启动流程（main.ts）

```
app.whenReady()
 ├─ 初始化 userData 目录（skills/、agents/ 并注册为白名单根）
 ├─ 初始化服务：FileSystemService / SQLiteStore / BackupService / MCPManager
 ├─ refreshTlsSkippedHosts()：从持久化配置重建 TLS 跳过主机集
 ├─ registerTlsBypass()：注册 setCertificateVerifyProc
 ├─ 挂载 MCP 生命周期用量事件
 ├─ registerIpcHandlers()：注册全部 IPC 处理器
 └─ createWindow()：创建无边框主窗口
```

**关键点**：
- `OURCODE_USER_DATA` 环境变量可重定向数据目录（测试 / 多实例）。
- 单实例锁（`requestSingleInstanceLock`）：二次启动聚焦已有窗口，避免 userData 缓存争用。

### 4.2 服务清单

| 服务 | 模块 | 职责 |
| --- | --- | --- |
| FileSystemService | `electron/services/file-system.ts` | 文件读写、目录列举、chokidar 监听、大文件流式读写 |
| SQLiteStore | `electron/services/sqlite-store.ts` | 全部持久化（9 张表）、可选聊天加密、响应缓存 |
| CryptoService | `electron/services/crypto.ts` | AES-256-GCM、主密码派生、导出/导入加解密 |
| BackupService | `electron/services/backup.ts` | hot-exit 备份（未保存脏缓冲镜像） |
| LspServer | `electron/services/lsp.ts` | LSP over stdio，didOpen/didChange/诊断推送 |
| DebugAdapterClient | `electron/services/debug.ts` | DAP 客户端，单调试会话 |
| MCPManager | `electron/services/mcp-manager.ts` | MCP stdio + HTTP(SSE) 连接、自动重连、工具/资源/提示词 |

### 4.3 IPC 设计模式

**三种通道形态**：
1. `ipcMain.handle` / `invoke`（请求-响应）：绝大多数通道，如 `fs:readFile`、`store:getSessions`。
2. `ipcMain.on` / `send`（单向）：`llm:httpAbort`（中止请求）。
3. 主进程 → 渲染推送（`webContents.send`）：`fs:fileChanged`、`term:data:<id>`、`llm:httpChunk`、`lsp:diagnostics`、`update:status`、`window:maximized`。

**多窗口支持**：IPC 处理器通过 `BrowserWindow.fromWebContents(event.sender)` 定位发送窗口（窗口控制、终端归属），`broadcast()` 广播到所有窗口。

**终端归属**：每个 PTY 记录 `{pty, webContents}`，窗口关闭时清理该窗口所有终端（attachWindowLifecycle）。

### 4.4 安全设计

| 机制 | 实现 |
| --- | --- |
| 路径白名单 | `allowedRoots: Set<string>`；用户通过对话框打开的目录/文件、`fs:authorize`、watcher 注册的根被登记；`assertPathAllowed()` 在每个 fs:* 处理器入口校验（win32 大小写不敏感比较，防路径穿越） |
| TLS 按需跳过 | `tlsSkippedHosts`（持久化配置）+ `tlsDraftHosts`（未保存草稿的连接测试，请求结束即移除）；`setCertificateVerifyProc` 仅对显式选中的主机放行（0 = 信任，-3 = 默认校验） |
| 环境变量 | `isSafeEnvVarName` 正则校验，仅允许普通标识符 |
| Web 抓取限制 | `web:fetch` 仅 http/https、2MB 大小上限、超时中止 |
| LLM 代理 | `llm:http` 仅 http/https、流式 chunk base64 转发、按请求 id 维护 AbortController |
| MCP 配置写入 | `mcp:saveConfig` 校验目标路径不逃逸项目根（相对路径 `..` 拒绝） |
| 搜索保护 | `SEARCH_MAX_FILE_BYTES`（50MB）以上文件跳过搜索，防主进程阻塞 |

## 5. 渲染进程设计

### 5.1 状态管理（Zustand ×14）

| Store | 职责 |
| --- | --- |
| chatStore | **核心**：会话/消息/分支/Agent 循环/审批/检查点/用量，约 2500 行 |
| editorStore | 打开文件、偏好、行内补全状态 |
| configStore | API 配置分组 |
| uiStore | 面板布局、弹窗 |
| shortcutStore | 快捷键绑定 |
| pluginStore | 插件状态 |
| usageStore | 用量展示缓存 |
| memoryStore | 长期记忆 |
| workflowStore | 工作流模板 |
| problemsStore | LSP 诊断 |
| recentFilesStore | 最近文件 |
| debugStore | 调试会话状态 |
| aiCommandsStore | 自定义 AI 命令 |
| targetModeInstruction | 目标模式指令 |

**设计要点**：Zustand 允许在 React 之外 `useChatStore.getState()` 读写——这是 Agent 循环、子智能体、工具处理器在非组件环境中访问状态的先决条件。

### 5.2 主要组件树

```
App
└── MainLayout
    ├── TitleBar（无边框窗口控制）
    ├── ActivityBar（活动栏：文件/搜索/Git/插件/设置）
    ├── Sidebar（文件树 / 项目列表 / Agent 任务 / 用量）
    ├── Editor 区（TabBar + BreadcrumbBar + Monaco + DiffView + ProblemsPanel + DebugPanel）
    ├── ChatPanel（ChatMessages + ChatInput + AgentPanel + Arena + 审批对话框）
    ├── TerminalPanel（xterm 多标签）
    ├── SearchPanel（全文搜索/替换）
    ├── CommandPalette / QuickOpen / OnboardingModal / SettingsModal
    └── StatusBar（语言/编码/分支/更新）
```

### 5.3 编辑器与大文件

- Monaco 按需注册语言（`modelRegistry`、`monacoSetup`），60+ 扩展名 → 语言映射集中在 `shared/constants.ts`。
- **大文件分块流式加载**：
  1. `fs:openStream` 返回流 id + 首块（FileStreamStart：编码/BOM/总字节数）。
  2. 渲染进程 `readChunkBatch` 拉取（pull 模式），按 `loadProgress` 展示进度。
  3. 完成前编辑器模型渐进填充；超大文件降级为纯文本或只读预览。
- **写入保真**：`fs:openWriteStream` 携带 encoding + hasBom，保存时保留原编码与 BOM。
- **热退出备份**：脏缓冲在保存间隔由渲染进程 `backup:save` 镜像到主进程 BackupService，崩溃后 RestoreBackupsModal 恢复。

## 6. LLM 客户端与适配器设计

### 6.1 适配器模式

```
LLMRequest（统一内部格式）
   │
   ▼
LLMClient.sendLLMRequest(req, config, timeout)
   ├─ getAdapter(provider, apiFormat)  ← 按 provider 选择适配器
   │    apiFormat 覆盖时优先用覆盖格式
   ├─ 响应缓存层（responseCache）
   ├─ Anthropic prompt-caching 注入（providerCache）
   └─ 逐适配器协议转换 → 统一 LLMStreamChunk 流
```

| 适配器 | 协议 | 说明 |
| --- | --- | --- |
| OpenAIAdapter | Chat Completions | 同时服务 `azure`（deployments URL 方案）与 `custom` |
| ResponsesAdapter | OpenAI Responses API | 新式端点 |
| AnthropicAdapter | Messages API | 支持 thinking 块、cache_control |
| GeminiAdapter | generateContent | 流式 |
| OllamaAdapter | /api/chat | 本地 |
| DeepSeekAdapter / GroqAdapter | OpenAI 兼容 | 独立类便于定制 |

### 6.2 传输层（llm:http 代理）

渲染进程沙箱化的 fetch 受 CORS 限制，而很多 OpenAI 兼容网关（longcat、one-api、new-api）不带 CORS 头。方案：
- 渲染进程把请求（url/headers/body/stream 标志）通过 `llm:http` 交给主进程 `net.fetch`。
- 流式模式：先推 `llm:httpHeaders`（状态/头），再逐 chunk 推 `llm:httpChunk`（base64），最后 `llm:httpDone` / `llm:httpError`。
- 请求级 `skipTlsVerify` 走 `tlsDraftHosts` 临时放行（不影响持久化配置）。
- `llm:httpAbort` 单向中止。

### 6.3 响应缓存

- 开关：`llmResponseCache`（默认开）。
- 仅缓存确定性请求（`shouldCache`：temperature=0）。
- 缓存键 `buildCacheKey`：provider + model + 消息 + 参数（providerCache 不入键）。
- 命中时 `replayCached` 逐 chunk 回放，usage 归零并在 chunk 上携带 `cacheHit`（节省 token 数上报用量面板）。
- 仅**完整完成**的响应才落库（防中止/失败缓存脏数据）。

### 6.4 上下文窗口管理

`trimHistoryForContext(messages, modelId)`：
- 预算 = 模型 contextWindow × 80%（为回复留余量）。
- 超预算时从最旧消息开始丢弃（保留 system 与最新用户消息），插入「[上下文管理] 较早的 N 条消息已省略」提示。
- 模型元数据查表 `MODEL_METADATA`，未知模型按前缀匹配，兜底 128000。

### 6.5 工具调用历史重建

存储的 `ChatMessage.toolCalls` 是 UI 友好的 `{id,name,arguments(object)}`，LLM 适配器需要原始线格式 `{id,type,function:{name,arguments(string)}}`。`toRawToolCalls()` 做转换，防止第二轮历史重建时崩溃。

## 7. Agent 循环设计（chatStore 核心）

### 7.1 两种会话模式

| agentMode | 行为 |
| --- | --- |
| `chat` | 自由对话，可带工具调用（写操作走审批） |
| `agent` | 计划 + 执行合并模式：复杂任务先计划（plan 模式只读），批准后执行；简单任务直接执行 |

### 7.2 工具审批流（单工具）

```
Agent 发出 write_file 工具调用
   │
   ▼
pendingApproval = { sessionId, toolCall, preview }   ← ToolExecutor.getPreview 生成预览
   │
   ├─ 用户批准 → _approvalResolves.set(sessionId, true)  → 执行工具
   ├─ 用户拒绝 → _approvalResolves.set(sessionId, false) → 结果标记 rejected
   └─ 白名单命中（toolAllowlist）→ 跳过对话框直接放行
```

**关键设计**：`_approvalResolves` 按 **sessionId** 键控——支持并行会话各自等待自己的审批对话框而不互相覆盖。

### 7.3 批量审批（Agent 模式）

- 一个工具调用批次中多个写工具 → 聚合为 `batchApproval` 对话框。
- 用户三选一：`confirm`（逐个确认）/ `all`（本次全部放行）/ `reject`（全部拒绝）。
- 支持「始终允许该工具」（`toolAllowlist`，localStorage，键 `ourcode-tool-allowlist:<projectPath>`）。

### 7.4 澄清提问（ask_user_question）

- `pendingQuestion` 单例（含 sessionId），`_questionResolves` 按 session 等待。
- `questionGate` 三态：`auto`（自动回答）/ `confirm`（需确认）/ `dismissed`（静默跳过）。

### 7.5 Agent 运行记录与轨迹

- `startAgentRun` → `AgentRun`（8 态状态机）持久化。
- `agentTraces`（内存态）记录每个工具调用的实时状态：running → success/error/rejected。
- 工具调用轮数预算用尽 → 消息带 `EXHAUSTED_MARKER` 前缀，UI 渲染「继续」按钮 → `continueGeneration`。
- 并行会话支持：`runningSessionIds`、`activeRuns`（sessionId → runId）。

### 7.6 Checkpoint 快照

- 写工具执行前 `captureCheckpoint(sessionId, toolCall)` 读取目标文件当前内容（或标记不存在）。
- `checkpoint:revert` 在主进程恢复所有快照文件（存在则写回、不存在则删除），并广播 `fs:fileChanged` 让打开中的编辑器重载。
- 主 Agent 与子智能体共享该机制，保证所有 AI 编辑可回滚。

### 7.7 跨会话消息（send_message / list_agents）

- 所有会话在同一渲染进程 store，`list_agents` 直接查 `useChatStore.sessions`。
- `send_message` → `receiveInboundMessage`：入站策略 `accept`（空闲则触发目标 Agent 循环）/ `hold`（仅入历史）/ `refuse`（拒绝，报错返回）。
- **并发守卫**：`_inboundLaunches` 引用计数（而非布尔标志）防止「循环结束 count-- 与新循环启动瞬间」的竞态导致第三个循环误启动。

### 7.8 系统提示词构建

- 稳定前缀：通用行为准则（所有模式共用）。
- 模式专用段：plan 模式（只读探索+计划提交）、agent 模式（复杂任务计划、简单任务直行）。
- 每轮动态上下文：工作区规则（`.ourcoderules`）、技能索引、长期记忆（关键词匹配）、当前编辑器选区、自动检索相关文件。
- Git 状态（porcelain v1 + 最近提交）作为可选上下文注入，30s 轮询刷新。

## 8. 工具系统设计

### 8.1 工具分类

| 类别 | 工具 | 审批 |
| --- | --- | --- |
| 只读 | read_file / list_directory / get_directory_tree / search_files / search_in_files | 否 |
| 写 | write_file / edit_file / create_directory / delete_file | **是** |
| 执行 | run_command | **是** |
| Agent 控制 | manage_todo / submit_plan / ask_user_question / remember | 否（remember 受 aiAutoMemory 控制） |
| 委派 | run_subagent / list_agents / send_message | run_subagent 是 |
| 网络 | web_search / read_url | 否 |
| 动态 | skill__&lt;name&gt; / mcp__&lt;server&gt;__&lt;tool&gt; | 否（技能只读指令、MCP 用户自配） |

### 8.2 ToolExecutor

- 静态工具：`createToolRegistry()` 一次构建 + `toolMap` 索引。
- 动态工具：`refreshMcpTools()`（主进程 MCP 定义）+ `refreshSkillTools()`（工作区技能）。
- `getToolDefinitions(filter?)`：plan 模式按 `PLAN_TOOLS` 过滤；**按名称排序保证工具数组字节稳定**（提供商前缀缓存命中依赖字节一致）。
- `getPreview()`：为审批对话框生成人类可读摘要（写路径、替换片段、命令等）。
- 用量记录：skills/subagents/MCP 三类事件异步上报 `usage:record`。

### 8.3 工具实现要点

- 懒加载（`await import('@/services/tools/helpers')`）减少首屏加载体积。
- 工具处理器在**渲染进程**调用 `window.electronAPI`（读文件等），主进程再做路径校验——双层防护。

## 9. 子智能体设计（Subagent）

### 9.1 执行模型

```
run_subagent 工具（主 Agent 批处理中调用）
   │
   ▼
runSubAgent(opts)
   ├─ 解析定义：.ourcode/agents/<name>.md (frontmatter) → 全局 → 内置
   ├─ SubagentGuard（权限单调递减）：
   │    tools 白名单过滤（LLM 只见到允许的工具）
   │    checkCall 二次拦截（控制类工具 / 越权路径）
   ├─ 构建子智能体系统提示词（角色 + 环境 + 当前文件 + 技能索引 + 规则）
   ├─ 迭代循环（maxIterations，默认 10）：
   │    LLM 请求 → 工具调用批 → guard.checkCall → checkpoint → execute
   │    → 结果回填 messages
   ├─ Token 预算：def.maxTokensBudget 超限即停
   └─ 返回结构化报告（工具次数 / 修改文件 / 结果 / 遗留问题）
```

### 9.2 与主 Agent 的差异

| 维度 | 主 Agent | 子智能体 |
| --- | --- | --- |
| 审批 | 写操作需用户批准 | **自主执行**（继承父任务授权） |
| 控制工具 | 可用 | **禁用**（submit_plan/ask/manage_todo/run_subagent） |
| 权限 | 完整 | 定义声明的降级权限 |
| 迭代 | 轮数预算 | maxIterations + maxTokensBudget |
| 记录 | AgentRun | usage 事件（category=subagent） |
| 回滚 | Checkpoint | 同样捕获 Checkpoint |

## 14. 关键数据流（时序）

### 14.1 普通聊天消息

```
用户发送消息
  → chatStore.sendMessage
  → 构建 RequestMessage[]（system prompt + 历史 trimHistoryForContext + 当前消息）
  → sendLLMRequest（LLMClient）
  → getAdapter → llmFetch（主进程 llm:http 代理，流式 chunk 回传）
  → 逐 chunk：更新 streamingBySession → UI 流式渲染（Thinking 块 / 正文）
  → done：usage 统计 → 持久化消息 → saveSession
```

### 14.2 Agent 模式一次迭代

```
runAgentLoop
  → 请求 LLM（带工具定义）
  → 解析 toolCalls 批次
  → 按批次遍历：
       requiresApproval?
         ├─ 是 → pendingApproval → 用户决策（或白名单放行）
         └─ 否 → 直接执行
       write 工具 → captureCheckpoint（快照）
       ToolExecutor.execute → 结果
       appendToolResult → 记录 trace
  → 消息入库（assistant + tool 结果）
  → 若还有工具调用 → 继续下一轮；轮数用尽 → EXHAUSTED_MARKER
```

### 14.3 大文件打开

```
打开文件 → fs:openStream（首块 + 元数据）
  → 编辑器模型按 chunk 追加（loadProgress 进度条）
  → 完成 → OpenFile 就绪（编码/BOM/行尾保留）
  → 编辑 → 脏标记 → autoSave/手动保存 → fs:openWriteStream 流式写回
```

## 15. 设计决策记录（ADR）

| # | 决策 | 备选 | 理由 |
| --- | --- | --- | --- |
| ADR-1 | LLM 请求全部经主进程代理 | 渲染进程直连 | 规避 CORS；统一 TLS 跳过策略；请求级中止 |
| ADR-2 | 审批解析按 sessionId 键控 | 全局单例 | 支持并行会话各自等待审批 |
| ADR-3 | Agent 循环在渲染进程 | 主进程 | 复用 Zustand store、DOM 渲染流式输出；主进程保持轻量 |
| ADR-4 | 工具定义数组按名排序 | 固定注册顺序 | 提供商前缀缓存依赖字节稳定 |
| ADR-5 | SQLite（better-sqlite3） | IndexedDB/JSON 文件 | 同步事务、复杂查询、主进程独占 |
| ADR-6 | Web Worker 沙箱插件 | iframe / 主进程加载 | 隔离强、权限可控、实现简单 |
| ADR-7 | 子智能体权限单调递减 + 双层拦截 | 仅提示词约束 | 纵深防御，防越权工具调用 |
| ADR-8 | 入站并发守卫用引用计数 | 布尔标志 | 关闭「循环结束与新循环启动」竞态窗口 |
| ADR-9 | 写操作强制 Checkpoint | 无快照 | 所有 AI 编辑可回滚，降低用户风险 |
| ADR-10 | 大文件流式加载 | 全量读入 | 避免主进程内存膨胀、UI 阻塞 |

## 16. 异常处理与边界条件

| 场景 | 处理 |
| --- | --- |
| LLM 超时 / 中止 | AbortError 归一化为「请求超时，请稍后重试」；`llm:httpAbort` 中止并清理 AbortController |
| 上游 HTTP 错误 | 结构化 ChatError（auth/timeout/rate_limit/server...），友好文案 + 可折叠详情 |
| 响应超出大小 | `web:fetch` 硬上限 2MB，超限返回错误 |
| 无效 URL / 非 http(s) | 校验拦截，返回错误消息 |
| 文件不存在（写前快照） | checkpoint 标记 existed:false，回滚时删除 |
| MCP 服务器崩溃 | 自动重连（指数退避），intentionalStop 防僵尸 |
| 未知工具名 | 返回 `Error: Unknown tool`，不中断循环 |
| 会话消息编辑后重生成 | 截断到该消息，重放 LLM 请求 |
| 大文件搜索 | >50MB 跳过，防阻塞主进程 |
| 窗口关闭时终端存活 | attachWindowLifecycle 清理所属 PTY |
